    5. Internacionalização

    Uma aplicação internacionalizada exibe seus textos no idioma do usuário. O estudo de caso está em francês e inglês. O princípio é simples: as views não contêm mais texto, e sim chaves ([MENU.HOME]), e um dicionário para cada idioma associa um texto a cada chave. O idioma selecionado é armazenado em um cookie.

    O [Symfony] inclui um componente de tradução, o Translator, que já encontramos no Exemplo 09 para as mensagens de validação. Seus dicionários ficam na pasta [translations], com um arquivo por domínio e por idioma: [validators.en.yaml] (o domínio das mensagens de validação, Exemplo 09), [messages.en.yaml] (o domínio padrão, o dos nossos textos). O formato YAML permite chaves aninhadas: é assim que os dicionários das versões [ASP.NET Core MVC], [NestJS], [Spring MVC], [Flask] e [Laravel] do estudo de caso, exceto pela sintaxe. Para a sintaxe das próprias mensagens, escolhemos o formato ICU (International Components for Unicode), um padrão que a extensão [intl] do [PHP] sabe interpretar e que, por exemplo, permite flexionar o texto no plural. A formatação de datas e valores continua a mesma do Exemplo 16.

# messages: o domínio padrão; +intl-icu: as mensagens seguem a sintaxe ICU
# ({name}: um parâmetro; {n, plural, ...}: uma mensagem que depende de um número)
MENU:
    HOME: Accueil
    PRODUCTS: Produits
HOME:
    TITLE: Bienvenue
    HELLO: 'Bonjour {name} !'
    DATE: 'Nous sommes le {date}.'
PRODUCTS:
    TITLE: Nos produits
    NAME: Produit
    PRICE: Prix
    COUNT: '{n, plural, =0 {Aucun produit} one {# produit} other {# produits}} au catalogue.'

    O nome do arquivo é composto de três partes: o domínio ([messages], o domínio padrão), o sufixo [+intl-icu], que indica mensagens no formato ICU, e o idioma ([fr]). As chaves são agrupadas por tema por meio do aninhamento do YAML: o item de menu “Accueil” tem a chave [MENU.HOME], com os níveis separados por um ponto. Um texto pode conter parâmetros, escritos como [{name}], que são substituídos durante a tradução.

    • Linha 9: os apóstrofos delimitam uma string YAML; eles são necessários quando o texto contém caracteres que o YAML interpreta (chaves, dois-pontos etc.);
    • Linha 15: uma mensagem no plural. [{n, plural, ...}] seleciona uma forma conforme o valor do parâmetro [n]: [=0] para exatamente 0, [one] para o singular, [other] para o plural; [#] é substituído pelo número. As regras de plural dependem do idioma, e o ICU as conhece: em francês, 0 e 1 são singular, ao passo que em inglês 0 é plural (“0 products”). Isso é um avanço em relação ao “product(s)” usado nas versões anteriores do estudo de caso.

    <?php
// src/EventListener/SetLanguage.php: o idioma de cada requisição

namespace App\EventListener;

use Symfony\Component\EventDispatcher\Attribute\AsEventListener;
use Symfony\Component\HttpKernel\Event\RequestEvent;
use Symfony\Component\HttpKernel\KernelEvents;

// priority 20: depois do roteamento, antes dos listeners do Symfony que usam o idioma (veja o exemplo 16)
#[AsEventListener(event: KernelEvents::REQUEST, priority: 20)]
class SetLanguage
{
    // os idiomas suportados; o primeiro é o idioma padrão
    public const LANGUAGES = ['en', 'fr'];

    public const COOKIE = 'language';

    // o idioma do cookie [language] se for suportado, inglês caso contrário
    public function __invoke(RequestEvent $event): void
    {
        $request = $event->getRequest();
        $language = $request->cookies->get(self::COOKIE);
        $request->setLocale(in_array($language, self::LANGUAGES, true) ? $language : self::LANGUAGES[0]);
    }
}

    Este é o listener [SetLanguage] do Exemplo 16, que desta vez obtém o idioma de um cookie:

    • linha 11: o listener do evento [kernel.request], com prioridade 20: depois do roteamento, mas antes dos listeners do [Symfony] que usam o idioma da requisição (Exemplo 16);
    • linhas 15–17: os idiomas aceitos e o nome do cookie: constantes de classe públicas, acessíveis a partir de outras classes ([SetLanguage::LANGUAGES]);
    • linhas 22–24: o idioma da requisição: o idioma do [language] cookie, se existir e for aceito; caso contrário, o inglês. [$request->cookies] é o conjunto de cookies enviados pelo navegador (exemplo 05); [get] devolve o valor de um cookie ou [null]. [in_array], com [true] como terceiro parâmetro, compara também os tipos ([===]). [setLocale] define o idioma da requisição: é o idioma usado pelo tradutor, por nossos filtros de formatação e pelo filtro [format_currency] do [Twig].

    Diferentemente do [Laravel], o [Symfony] não criptografa os cookies: o cookie [language] é transmitido em texto simples. Isso não é um problema: ele não contém nenhuma informação confidencial, e o servidor aceita apenas idiomas suportados. O exemplo seguinte retoma a questão de quanta confiança se pode depositar em um cookie.

    <?php
// src/Controller/LanguageController.php: a escolha do idioma

namespace App\Controller;

use App\EventListener\SetLanguage;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Cookie;
use Symfony\Component\HttpFoundation\RedirectResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\Routing\Attribute\Route;

class LanguageController extends AbstractController
{
    // GET /language/fr: armazena a escolha em um cookie e depois volta à página anterior.
    // requirements: um idioma diferente de en ou fr não corresponde à rota (404)
    #[Route('/language/{code}', name: 'language', requirements: ['code' => 'en|fr'], methods: ['GET'])]
    public function change(Request $request, string $code): RedirectResponse
    {
        $response = $this->redirect(self::originPage($request));
        // o cookie: um ano de vida, ilegível pelo JavaScript da página (httpOnly),
        // nunca enviado com uma requisição POST vinda de outro site (sameSite lax)
        $response->headers->setCookie(Cookie::create(SetLanguage::COOKIE, $code)
            ->withExpires(new \DateTimeImmutable('+1 year'))
            ->withHttpOnly(true)
            ->withSameSite(Cookie::SAMESITE_LAX));
        return $response;
    }

    // a página de onde viemos (cabeçalho Referer), da qual guardamos apenas o caminho:
    // redirecionar para um endereço completo vindo da requisição permitiria
    // enviar o usuário a outro site (falha de "open redirect")
    private static function originPage(Request $request): string
    {
        // parse_url divide uma URL em seus componentes (caminho, parâmetros...)
        $url = parse_url($request->headers->get('Referer', ''));
        $path = $url['path'] ?? '';
        // "//site.com/..." seria entendido pelo navegador como um endereço
        // em OUTRO site: recusado também
        if (! str_starts_with($path, '/') || str_starts_with($path, '//')) {
            return '/';
        }
        return isset($url['query']) ? "$path?{$url['query']}" : $path;
    }
}
    • linha 17: a rota [/language/{code}]. A opção [requirements] (exemplo 02) limita o parâmetro aos dois idiomas aceitos: [/language/de] não corresponde a nenhuma rota e devolve um erro 404;
    • linha 20: a ação responde com um redirecionamento para a página de onde o usuário veio: o usuário volta à sua página, já no novo idioma;
    • Linhas 23–26: a resposta contém um cookie, que o navegador reenviará a cada requisição. A classe [Cookie] do [Symfony] o descreve: [Cookie::create(name, value)] o cria, e cada método de [with...] devolve uma cópia modificada (um objeto imutável; veja o Exemplo 03): [withExpires], a data de expiração (em um ano); [withHttpOnly(true)] o torna invisível para o [JavaScript] da página; [withSameSite(Cookie::SAMESITE_LAX)] impede que o navegador o envie com uma requisição POST de outro site. ([httpOnly] e [lax] são, aliás, os valores padrão de [Cookie::create].) [$response->headers->setCookie] o adiciona à resposta como um cabeçalho [Set-Cookie];
    • linhas 33–44: a página de origem é indicada pelo cabeçalho [Referer] da requisição (a grafia incorreta, com um único [r], é a usada no padrão HTTP), que o navegador preenche com a URL da página que continha o link. Mas esse cabeçalho vem do cliente, que pode colocar qualquer coisa nele. Redirecionar cegamente para esse endereço transformaria nossa aplicação em um redirecionamento aberto: um link malicioso com o nome do nosso domínio poderia enviar o usuário a um site malicioso. Por isso, mantemos apenas o caminho e os parâmetros da URL (a função [parse_url] do [PHP] a decompõe em seus componentes em um array associativo) e rejeitamos qualquer caminho que comece por [//], que o navegador interpretaria como o endereço de outro site.

// src/Controller/PagesController.php: as actions nada sabem sobre o idioma:

namespace App\Controller;

use App\Model\Product;
use DateTimeImmutable;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route(methods: ['GET'])]
class PagesController extends AbstractController
{
    #[Route('/', name: 'home')]
    public function home(): Response
    {
        return $this->render('pages/home.html.twig', ['name' => 'Marie',
            'today' => new DateTimeImmutable('2026-09-23')]);
    }

    #[Route('/products', name: 'products')]
    public function products(): Response
    {
        return $this->render('pages/products.html.twig', ['products' => [
            new Product('Keyboard', 2500),
            new Product('Mouse', 1250),
            new Product('Screen', 114900),
        ]]);
    }
}

    As ações são agnósticas quanto ao idioma: fornecem dados brutos (um nome, uma data, valores em centavos). A tradução e a formatação ficam a cargo das views. A classe [Product] tem um nome e um preço em centavos; a extensão [FormatsExtension] é a do Exemplo 16: seu filtro [long_date] escreve uma data no formato “completo” do idioma da requisição (“Wednesday, September 23, 2026”, “mercredi 23 septembre 2026”), e seu filtro [money] escreve um valor monetário.

    Outra maneira de escolher o idioma seria ler o cabeçalho [Accept-Language] do navegador (exemplo 12; [$request->getPreferredLanguage(['fr', 'en'])] seleciona o melhor idioma dentre os aceitos).
