    13. Apêndices

    13.1. Instalação do PHP

    Os exemplos e o estudo de caso exigem o [PHP] 8.4 ou posterior (o [Symfony] 8 o exige), com as extensões [intl] (formatação de números e datas, exemplo 16, e mensagens ICU, exemplo 22), [pdo_mysql] (acesso ao [MySQL], exemplo 28 e estudo de caso), [mbstring], e [openssl]. Foram testados com a versão 8.4.

    No [Windows], o mais simples é o [Laragon] (laragon.org), que instala o [PHP], o [Composer], um servidor [MySQL] e a ferramenta de administração [HeidiSQL]. Se a versão fornecida do [PHP] for anterior à 8.4, baixe uma versão mais recente em windows.php.net/download (versão Thread Safe , arquivo [.zip]) e extraia-a na pasta [bin\php] dentro do [Laragon]; o menu PHP / Version do [Laragon] permite então selecioná-la. O menu PHP / Extensions ativa uma extensão com um único clique ([intl], [pdo_mysql]). O terminal do [Laragon] (botão Terminal) aceita os comandos [php], [composer] e [mysql].

    Sem o [Laragon], extraia o arquivo do [PHP] em uma pasta ([C:\php]), adicione essa pasta à variável de ambiente [Path], depois crie o arquivo de configuração [php.ini] copiando o [php.ini-development] e remova o ponto e vírgula que comenta as linhas das extensões necessárias:

    1
2
3
4
    extension=intl
extension=mbstring
extension=openssl
extension=pdo_mysql

    No [macOS], o gerenciador de pacotes [Homebrew] instala o [PHP] e suas extensões padrão: [brew install php]. No [Linux] ([Ubuntu]), a versão fornecida pela distribuição costuma ser mais antiga; o repositório [ppa:ondrej/php] oferece as versões mais recentes:

    1
2
    sudo add-apt-repository ppa:ondrej/php
sudo apt install php8.4-cli php8.4-intl php8.4-mbstring php8.4-mysql php8.4-xml php8.4-curl php8.4-zip

    Verifique a instalação em um novo console:

    1
2
    php -v
php -m

    O primeiro comando deve exibir um número de versão igual ou superior a 8.4 (por exemplo, [PHP 8.4.12]); o segundo lista as extensões carregadas, entre elas [intl] e [pdo_mysql]. O comando [php --ini] indica qual arquivo, [php.ini], está sendo usado.

    13.2. Composer

    [Composer] é o gerenciador de bibliotecas do [PHP] (getcomposer.org). Ele é fornecido pelo [Laragon]; para o [Windows], mas sem o [Laragon], usa-se seu instalador ([Composer-Setup.exe]); para o [macOS], use [brew install composer]; para o [Linux], siga as instruções da página getcomposer.org/download. Verifique a instalação:

    1
    composer -V

    Comandos úteis em uma pasta de projeto (aquela que contém o [composer.json]):

    1
2
3
4
5
    composer install              # instala as bibliotecas do projeto (pasta vendor)
composer show                 # as bibliotecas instaladas
composer update               # passa para as versões mais recentes permitidas por composer.json
composer require name/package # adiciona uma biblioteca ao projeto
composer dump-autoload        # reconstrói o carregador de classes (após adicionar uma pasta de classes)

    [Composer] baixa as bibliotecas do repositório [Packagist] (packagist.org): é necessária uma conexão com a Internet durante a instalação. Se você estiver atrás de um proxy corporativo, especifique o proxy por meio das variáveis de ambiente [HTTP_PROXY] e [HTTPS_PROXY]. A pasta [vendor] não é copiada de uma máquina para outra (ela pode conter caminhos absolutos e é volumosa); ela é recriada com [composer install]. Por isso ela não está incluída nos materiais do curso. A pasta [examples] contém seu próprio [vendor], compartilhado pelos 28 exemplos; o estudo de caso tem o seu.

    O estudo de caso usa o componente [Runtime] do [Symfony], que também é um plugin do [Composer]: é esse componente que gera o arquivo [vendor/autoload_runtime.php] lido por [public/index.php]. [Composer] pede permissão para executar um plugin; o arquivo [composer.json] da aplicação a concede (seção [allow-plugins]). No [Linux], o [Composer] se recusa a executar plugins quando iniciado pela conta [root], a menos que a variável de ambiente [COMPOSER_ALLOW_SUPERUSER] esteja definida como [1]: sem ela, o arquivo [autoload_runtime.php] estaria ausente (veja “Problemas comuns” no estudo de caso). É melhor não trabalhar com a conta [root].

    13.3. Instalação do Visual Studio Code

    [Visual Studio Code] é baixado em code.visualstudio.com. Adicione três extensões (menu View / Extensions):

    • PHP Intelephense: autocompletar código, navegação pelo código (inclusive o código do [Symfony], localizado na pasta [vendor]) e relatório de erros;
    • Twig Language 2: realce de sintaxe e autocompletar para as views [Twig] (arquivos [.html.twig]);
    • YAML (da [Red Hat]): realce de sintaxe e validação dos arquivos de configuração ([config/packages/*.yaml]) e dos dicionários ([translations/*.yaml]).

    A extensão PHP Debug permite executar o código passo a passo usando o depurador [Xdebug] (uma extensão do [PHP], a ser instalada separadamente: xdebug.org).

    Abra a pasta [examples] ou a pasta do estudo de caso (menu File / Open Folder). O terminal integrado (menu Terminal / New Terminal) permite iniciar as aplicações e executar os comandos [php bin/console ...] sem sair do editor.

    13.4. Instalação do MySQL com o Laragon

    [Laragon] instala um servidor [MySQL] pronto para uso no [Windows], junto com a ferramenta de administração [HeidiSQL]. Após a instalação:

    • o botão "Start All" inicia o servidor [MySQL] na porta 3306;
    • o usuário [root] não tem senha: esses são os valores da variável [DATABASE_URL] dos arquivos [.env] do exemplo 28 e do estudo de caso ([mysql://root:@127.0.0.1:3306/...]);
    • o botão Database abre o [HeidiSQL], onde o menu File / Run File SQL executa os scripts [dbpersons.sql] (exemplo 28) e [dbrdvmedecins2.sql] (estudo de caso).

    No [Linux] ou no [macOS], instale o [MySQL] ou o [MariaDB] usando o gerenciador de pacotes do sistema e execute os scripts com o cliente de linha de comando [mysql]. O driver [pdo_mysql] funciona com ambos sem nenhuma configuração. No [Linux], a conta [root] do [MariaDB] costuma ser configurada para entrar apenas pela conta do sistema [root] ([sudo mysql]): cria-se então um usuário para as aplicações, que é indicado na variável [DATABASE_URL] do arquivo [.env] ([mysql://course:course@127.0.0.1:3306/...]) de cada uma:

    1
    sudo mysql -e "CREATE USER 'course'@'localhost' IDENTIFIED BY 'course'; GRANT ALL ON *.* TO 'course'@'localhost';"

    Com o [MariaDB], também se indica sua versão na variável [DATABASE_URL] ([serverVersion=10.11.2-MariaDB] em vez de [serverVersion=8.0.32], por exemplo): [Doctrine] adapta o SQL que escreve ao banco de dados utilizado.

    13.5. Instalação do curl

    [curl] já vem incluído no [Windows] 10 e 11, no [macOS], e na maioria das distribuições [Linux]. No [PowerShell], é preciso digitar [curl.exe], e não [curl]: nas versões mais antigas do [PowerShell], [curl] é um alias de outro comando ([Invoke-WebRequest]), que tem opções diferentes. No prompt de comando do [Windows] ([cmd]), as aspas de uma string JSON são escritas como [\"] (exemplo 11), e uma URL que contenha [&] deve ser colocada entre aspas duplas.

    13.6. A ferramenta symfony

    [Symfony] oferece uma ferramenta de linha de comando, o programa [symfony] (Symfony CLI), que não é necessária para acompanhar este documento, mas é mencionada ao longo da documentação. Ela é instalada seguindo as instruções da página symfony.com/download: no [Windows], com o gerenciador de pacotes [Scoop] ([scoop install symfony-cli]); no [macOS], com o [Homebrew] ([brew install symfony-cli/tap/symfony-cli]); no [Linux], com o gerenciador de pacotes do sistema. Os comandos mais úteis:

    1
2
3
4
    symfony check:requirements      # a configuração do PHP é adequada para o Symfony?
symfony new my-project --webapp # um novo projeto completo (veja a introdução)
symfony server:start            # um servidor de desenvolvimento (http://127.0.0.1:8000)
symfony console debug:router    # equivalente a php bin/console debug:router

    Seu servidor de desenvolvimento faz o mesmo que [php -S localhost:8000 -t public], com algumas vantagens: ele localiza sozinho a pasta [public], pode servir o site em HTTPS (após [symfony server:ca:install]), pode rodar em segundo plano ([symfony server:start -d], depois [symfony server:stop]) e seleciona a versão do [PHP] do projeto quando várias versões estão instaladas. O servidor embutido no [PHP], usado neste documento, tem a vantagem de não exigir instalação.
